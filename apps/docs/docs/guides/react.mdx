React is a platform layer on top of the JavaScript and TypeScript base. Treat it as the UI and state-management shell around Mesh Link JS, not as the place where the mesh model itself should live.

## What this platform is for

Use the React platform route when you want to:

- render mesh state in a browser UI,
- coordinate scans, provisioning, and model commands from components,
- and keep the actual mesh logic in shared services instead of inside component trees.

## Recommended composition

A typical React setup looks like this:

- `@mesh-link-js/core` owns mesh state and messages.
- `@mesh-link-js/utils` owns persistence and shared helper types.
- `@mesh-link-js/sdk-web` handles browser transport concerns.
- React owns UI state, effects, and user workflows around those services.

## Practical guidance

Keep transport and mesh orchestration in plain TypeScript modules or service objects. Let React subscribe to that state, trigger actions, and render progress. That keeps the base layer portable if you later need a different UI shell.
