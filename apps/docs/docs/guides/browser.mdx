The browser route is where someone should be able to explore the SDK with the least setup. It is the right place for direct experimentation, demos, and eventually a true in-doc simulator.

## What this route is for

- Trying out mesh transport ideas without committing to a full mobile app flow.
- Understanding how the browser transport layer differs from the higher-level package composition route.
- Creating a future home for direct browser simulation inside the docs.

## What you can do right now

- Read the [Web Guide](/docs/guides/web) to understand the current browser-oriented package.
- Use the [Web Transport API](/docs/api/web) reference to inspect the low-level exports available today.
- Use the rest of the docs to understand the core mesh concepts and data flow even before a full simulator is added.

## What is planned for this route

This route is intentionally called out early because it should become the no-setup entrypoint for trying the SDK directly in the browser.

That means the long-term goal for this page is:

- a browser-based simulator or playground,
- a guided transport flow that can be explored without local setup,
- and a lighter-weight way to understand messages, provisioning states, and event flow.

Until that lands, the important thing is that the route exists and sets the expectation correctly instead of implying the experience already exists.
