Once a device is part of the mesh and reachable through a proxy connection, most application code comes down to finding the right model and sending the right message.

## Find the model you want

Use your runtime adapter to locate the model on a node, then keep the core model identifier in view. The important part is not the wrapper type, but the fact that you are targeting a specific model ID on a specific element.

## Bind an application key if needed

Any higher-level model helper still depends on the target model being bound to the correct application key. Whether that binding happens through a convenience wrapper or a direct config message depends on the adapter you are using.

The helper above creates `GenericOnOffGet` and `GenericOnOffSet` messages from `@mesh-link-js/core` and delegates the actual send path to whatever transport or runtime adapter your application owns.

## When to drop to raw messages

Use raw core messages when:

- The model extension you need does not exist yet.
- You want to control the exact message class being sent.
- You are building a new extension on top of the core transport and message system.
