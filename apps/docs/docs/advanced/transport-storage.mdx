Transport and storage are the two seams that make Mesh Link JS portable across runtimes.

## Transport abstraction

The transport layer moves mesh traffic between your app and nearby devices.

That transport changes by runtime:

- React Native uses native BLE APIs,
- Node.js usually uses a host adapter or USB dongle,
- Web uses Web Bluetooth where supported,
- the simulator replaces radio traffic with deterministic in-memory events.

The point of `createMesh()` is to keep that difference below the application flow.

## Storage design

Mesh networks are stateful. Keys, addresses, scenes, and topology must survive process restarts.

```ts
const mesh = await createMesh({
  storage: { driver: "file", path: "./mesh-state.json" },
})
```

Persist at least:

- network keys,
- application keys,
- provisioned device metadata,
- group definitions,
- scenes.

## Operational implications

Transport and storage decisions affect product behavior directly.

- Unreliable transport increases retry pressure.
- Weak persistence makes recovery and multi-session support harder.
- Shared storage between services needs explicit coordination.

For production systems, decide early where the mesh state database lives and which runtime owns it.
