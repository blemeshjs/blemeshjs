The base layer of Mesh Link JS is plain JavaScript and TypeScript. Start here if you want to understand the package boundaries, the mesh object model, and the runtime seams before choosing a platform.

## What base means in this project

The base of Mesh Link JS is the set of shared packages and concepts that do not belong to any one UI framework or runtime:

- `@mesh-link-js/core` for mesh state, provisioning, messages, and bearers.
- `@mesh-link-js/utils` for storage, identifiers, typed helpers, and shared support code.
- Runtime seams for transport, persistence, and event flow.
- Higher-level adapters that compose those pieces for a specific environment.

## What you will touch in code

Most integrations start from a small set of shared concerns:

- mesh state and messages from `@mesh-link-js/core`,
- persistence and helper types from `@mesh-link-js/utils`,
- a transport implementation for the runtime you are targeting,
- and a thin adapter layer that keeps runtime-specific details out of the rest of the codebase.

That base stays stable even when the platform layer changes from Node to React Native to a web UI framework.
