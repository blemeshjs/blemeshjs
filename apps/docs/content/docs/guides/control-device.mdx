Use this recipe when the device is already provisioned and you need the fastest current control path.

## 1. Discover a provisioned device

<Tabs items={["Web", "React Native", "Node"]}>
  <Tab value="Web">
    ```ts
    mesh.connection.on("scan:new-proxy", async (proxy) => {
      await mesh.connection.connect(proxy);
    });

    mesh.connection.scan({ timeout: 10_000 });
    ````
    <Callout>
      On the web you can't scan and see get a list of devices like on other platforms due to [this limitation](https://github.com/WebBluetoothCG/web-bluetooth/blob/main/implementation-status.md#scanning-api).
      You'd rather get a sub window showing scanned devices and the device you select would emit a `scan:new-proxy` event.
    </Callout>

## 3. Send the model command

Once the proxy connection is established, move up to the model layer described in the SDK package reference.

The current docs do not present `device.light.on()` as the public source of truth anymore. For the accurate exported surfaces, use:

- [SDK Package](/docs/api/sdk)
- [Core Package](/docs/api/core)

## Expected behavior

- the SDK opens a session to the device,
- the selected proxy remains reachable,
- your model command path can be layered on top of a real connection.

## What this page is really for

This guide exists to place lighting control in the correct flow order:

1. configure the supported runtime,
2. discover a provisioned proxy,
3. connect cleanly,
4. then send mesh model messages.

## When to use models directly

If you need lower-level control, work through the model API:

```ts
import { GenericOnOff } from "@blemeshjs/sdk";
```

Use the generated package docs for the current signatures and related model message types.
